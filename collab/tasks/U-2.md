## Scope
One self-contained `serverlab/ui/static/index.html` (inline CSS and JS, NO external requests of any kind: no CDN, no web fonts, no frameworks) that implements the UI described in docs/phases/ui.md section 1 against the JSON API in docs/ui-api.md. The server (already built) replaces `__SERVERLAB_TOKEN__` in the page; read the token from `<meta name="serverlab-token" content="__SERVERLAB_TOKEN__">` and send it as header `X-Serverlab-Token` on every POST.

## Requirements
- Three tabs: **Experiments**, **Results**, **Predictions**; a job panel docked at the bottom on every tab (state, elapsed, last log lines in a scrolling monospace box, Cancel button). Poll `/api/jobs/current` every 1 s only while a job is running or just started; stop when it is no longer `running`. When a finished job has `result_dir`, offer a button to open that result.
- **Experiments:** one card per spec (name, condition chips, kind badge, repetitions). Buttons: *Show schedule* (action `schedule`), *Run* (`run`), *Sweep* (only when kind is `sweep`; `run` only when kind is `experiment`), and a global *Validate (offline)*. Run/Sweep first ask for confirmation in a dialog: "This starts Docker containers and takes minutes. Close other heavy apps and keep the laptop plugged in." A spec with `error` shows the error and disables its buttons. A collapsed "Paste a spec" area with a textarea and action select posts `{"action","yaml"}`. Show 400/409 errors from the server (`{"error": ...}`) inline.
- **Results list:** table (experiment, time parsed from the timestamp `YYYYMMDDTHHMMSSZ`, kind, runs, invalid, warning count, comparability). Clicking a row opens the detail view with a back button.
- **Result detail:** (1) environment card; if `environment.warnings` is non-empty show a prominent amber banner listing each warning; always show the `comparability` value. (2) schedule as an ordered row of chips, one color per condition. (3) runs table sorted by `index`: status pill (valid / invalid), condition, repetition, offered rate, completed, dropped, p50, p99, SUT CPU (usec -> "x.x ms CPU"), reasons shown under invalid rows. (4) for each run, links for its `metrics` kinds (`docker`, `app`, `pg`) that fetch `/api/results/.../metrics/{run_id}/{kind}` and draw a small SVG time series (app: `requests_waiting` and `pool_available`; docker: `cpu_percent` per container; pg: counts per wait event as a stacked bar per sample). (5) for `sweeps`: one panel per sweep (condition + repetition) with an inline SVG chart: x = offered rate (log scale), left panel achieved throughput vs offered with a y = x reference line, right panel P99 (log y); points colored AND shaped by status (ok = circle, saturated = triangle, invalid-other = cross) so it is readable without color; the knee bracket `[lo, hi]` as a shaded band with the estimate as a line; a table of the steps under the chart (rate, status, achieved, p99, k6 CPU %, note); knee status and warnings as text. `null` values display as "n/a", NEVER as 0.
- **Predictions:** fetch `/api/predictions` and render the markdown with a small safe renderer written by you (headings, paragraphs, bullet/numbered lists, tables, inline code, bold, code fences). It must escape all HTML.
- **Safety:** every string from the API is inserted with `textContent` or escaped; never use `innerHTML` with unescaped data.
- **Design:** clean, calm, readable. CSS variables for colors; light theme by default and a dark theme under `@media (prefers-color-scheme: dark)`; system font stack; 16 px side gutters, works at 360 px phone width (tables scroll horizontally inside their container, no page-level horizontal scroll); visible focus outlines; buttons are real `<button>`s; the job state uses `aria-live="polite"`. Contrast at least WCAG AA in both themes. Sensible empty states ("No results yet. Run an experiment from the Experiments tab.").

## Rules for testing (important)

- Run the server from your worktree against the real data: `uv run serverlab ui --root <repo> --port 8791 --no-open` (in the background; stop it when done). Real results exist there (week2_demo, week2_overhead, validate_synthetic, week4_*).
