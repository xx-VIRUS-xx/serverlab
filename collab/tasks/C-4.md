## Scope
Implement `MetricsCollector` (`start(run_id, out_path)`, `stop() -> CollectorStats`) per docs/phases/week2.md s2-3. One `docker stats --format '{{json .}}'` streaming subprocess on the host (not inside the SUT), writes one JSON line per container per sample with a host timestamp, interval >= 1 s (reject lower). A failure in the collector must never raise into the caller: record it in `CollectorStats` (samples, missed, errors, interval). Parsing must be unit-tested on fixtures captured from the real `docker stats` on this Mac, not invented numbers.

## Acceptance
- [x] Real capture of a short run against a running container; paste the first lines of the jsonl.
- [x] Interval < 1 s raises ValueError at construction.
- [x] Subprocess is terminated on stop(), and on failure no zombie process remains.
- [x] ruff, mypy, pytest clean.

## Evidence

Implementation: `serverlab/metrics/collector.py` (`DockerStatsCollector`, `CollectorStats`, parsers), tests in `tests/metrics/test_collector.py` (35 tests). Fixtures are verbatim lines from `docker stats --format '{{json .}}'` (Docker 29.5.2) against an `alpine` container `sl-c4`, embedded in the test file.

**Real capture (raw stream, pipe mode).** Docker prefixes each frame with terminal codes (`ESC[H`, `ESC[K`, `ESC[J`) and emits blank lines when stdout is a pipe. The collector strips these before parsing. First frame, idle:

Busy frame (`yes` running): `"CPUPerc":"204.14%"`, `"MemUsage":"912KiB / 7.737GiB"`, `"PIDs":"3"`. CPU above 100% is valid and is kept as-is.

Observation for Claude: docker delivered about 2 frames per second here (9 frames in ~4.5 s, 4 written, 5 dropped at `interval_s=1.0`), so sample gaps were 1.0 to 1.5 s. **Deviations from the task text**, following the lead's brief:
- `CollectorStats` fields are `samples`, `parse_errors`, `dropped_by_downsampling`, `interval_s`, `errors`. The task text said `missed`; the brief's `dropped_by_downsampling` replaces it.
- The class is `DockerStatsCollector`, not `MetricsCollector`.
- `parse_errors` counts per unparseable field (or per non-JSON line). The field is set to null.
- Added a read-only `pid` property (used by the zombie test).
- Unit-conversion tests (`parse_size("1.2kB")` and similar) use synthetic unit strings. The data fixtures are all real captures.
