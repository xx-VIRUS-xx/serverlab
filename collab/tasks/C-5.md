## Scope
The synthetic target currently answers one request per TCP connection (`Connection: close`). Add HTTP/1.1 persistent connections (loop reading requests on the same connection, honour `Connection: close` from the client, idle timeout), keeping the capacity formula exact (semaphore, fixed service time, no randomness) and the existing endpoints and tests green.
Measure and record the throughput ceiling: with the capacity configured far above the offered rate (e.g. CONCURRENCY_LIMIT=1000, SERVICE_TIME_MS=1), real k6 at increasing rates against the container pinned to 1 CPU (`docker run --cpuset-cpus 0`, k6 from the pinned image `grafana/k6@sha256:e66db15b860113878fa74670e31f5e274830b7b6e42c8bff28b2f2d86a257603` pinned to another CPU, same docker network) — report the highest rate with 0 dropped iterations. Do not claim a ceiling you did not measure.

## Evidence

Implementation: `targets/synthetic/app.py` loops per connection (`_serve_one` until it returns False). `Connection: close` from the client ends the loop after a `Connection: close` reply. Idle timeout `IDLE_TIMEOUT_SECONDS = 30.0` applies to waiting for the next request head. Malformed heads, bad versions, bad Content-Length and handler exceptions close only that connection. Request bodies (Content-Length) are read and discarded so framing stays correct. Service time, semaphore and stats code are unchanged.

Tests: `tests/targets/test_synthetic_keepalive.py` (new, 4 tests). `tests/targets/test_synthetic.py` is unchanged.

### Ceiling measurement

Image: `docker build -f targets/synthetic/Dockerfile -t sl-synth-c5 .` (built OK).
Target: `docker run -d --name c5-target --network c5net --cpuset-cpus 0 -e CONCURRENCY_LIMIT=1000 -e SERVICE_TIME_MS=1 sl-synth-c5`
k6: `grafana/k6@sha256:e66db15b860113878fa74670e31f5e274830b7b6e42c8bff28b2f2d86a257603`, `--cpuset-cpus 2`, same network, script `/private/tmp/claude-501/c5/load.js` (constant-arrival-rate, timeUnit 1s, duration 15s, preAllocatedVUs 200, maxVUs 2000, GET `http://c5-target:8000/work`, status check). The script was copied in with `docker cp` because the bind mount of `/private/tmp` was not visible to the k6 container. The `--summary-export` write failed with permission denied inside the container, so the figures below come from the k6 end-of-test summary on stdout.
