## Scope
k6 does not emit HDR histograms. Build them from k6 per-request output (`--out json` or csv, whichever A-1 settled on).

- `build_hdr(request_durations_ms) -> HdrHistogram` using the `hdrhistogram` package. Fixed range and significant digits, documented in the module docstring.
- `write_hdr(hist, path)` -> `raw/run_<cond>_<n>.hdr` (standard compressed HDR encoding so histograms can be merged later in Week 3).
- Streaming parse: must not load a multi-GB output file into memory.

## Out of scope
Merging and percentiles across runs (Week 3).

## Acceptance
- [x] Round trip: write then read gives identical counts and percentiles.
- [x] Percentiles from the HDR agree with the k6 summary percentiles within the HDR precision bound. Paste the comparison.
- [x] Memory stays flat on a 1M-line synthetic input (state how measured).
- [x] ruff, mypy, pytest clean.

Deviations:
- `per_request_path` is `hdrcheck_points.json`, not `hdrcheck.json`. The adapter's default summary path is `<out_dir>/<run_id>.json`, so passing `<tmp>/hdrcheck.json` as per_request_path made k6's summary export overwrite the NDJSON file (first attempt failed with a JSON parse error at line 1, which the strict parser caught). Potential bug in `serverlab/load/k6.py` for lead: the adapter does not guard against the two paths colliding. Not changed here (outside `files:`).
- The k6 comparison is a manual script, not a pytest test, so unit tests need neither k6 nor a server.
- `hdrhistogram` 0.10.8 does not enforce its configured range: `record_value(60_000_001)` and `record_value(0)` return True. Range is therefore checked in `hdr.py`; out-of-range values are counted, not recorded.
