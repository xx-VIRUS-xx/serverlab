## Scope
Implement `K6Adapter` against the `LoadAdapter` protocol in `serverlab/load/base.py` (owned by Claude, created in L-2).

- Generate a k6 script for `constant-arrival-rate` (rate, duration, preAllocatedVUs, maxVUs, target URL, method, headers, body). Open-loop only.
- Run k6 (subprocess, `--summary-export` JSON plus per-request output path supplied by caller), return a `RunResult`.
- Parse the summary: planned iterations, completed, `dropped_iterations`, VU peak, `http_req_duration` percentiles, error rate.
- Validity: `invalid` if `dropped_iterations / planned > 0.005` or peak VUs reached `maxVUs`. Set `invalid_reasons: list[str]`.

## Out of scope
HDR export (A-2). Ramping executors. Any other load tool.

## Acceptance
- [x] Generated script is deterministic for equal inputs (snapshot test).
- [x] Summary parser tested on at least 3 fixture summaries: clean, dropped>0.5%, maxVUs hit. Fixtures are real k6 output captured with the installed k6, not hand-invented numbers.
- [x] Invalid reasons are specific strings, not just a boolean.
- [x] ruff, mypy, pytest clean.

## Changes from review (CHANGES REQUESTED round 1)
1. **No silent fallbacks**: `med`, `p(90)`, `p(99)`, `max` are required in `http_req_duration`. Missing keys → `valid=False` with a reason naming the missing keys; zeros only as placeholders in that invalid case. `avg`/`p(95)` fallbacks removed.
2. **No fabricated peak VU**: removed `if peak_active == 0 and completed > 0: peak_active = 1`; `peak_vus = max(peak_active, peak_allocated)` only.
3. **Stale summary deleted**: `K6Adapter.run` now calls `target_summary_path.unlink()` before launching k6.
4. **New tests added**: `test_missing_percentile_key_marks_run_invalid` and `test_stale_summary_deleted_before_run`.
