## Scope
Same lifecycle as `serverlab/metrics/collector.py` (read it first and follow its conventions: `start(run_id, out_path)` returns immediately, `stop() -> stats`, never raises into the caller, errors recorded in stats, interval >= 1.0 s enforced with ValueError at construction).
`PgActivityCollector(dsn: str, interval_s: float = 1.0)`: one persistent host-side psycopg (v3, sync) connection in a background thread; every interval run
`SELECT state, wait_event_type, wait_event, count(*) FROM pg_stat_activity WHERE backend_type = 'client backend' AND pid <> pg_backend_pid() GROUP BY 1,2,3`
and write ONE JSON line per sample: `{"run_id","t_host_utc" (ISO, ms),"rows":[{"state","wait_event_type","wait_event","count"},...]}` (null values stay null). Use `autocommit=True` and a short statement timeout; if the connection drops, record the error, retry to connect on the next interval, count `missed_samples`. Stats model: samples, missed_samples, errors, interval_s.

## Tests
Integration tests against a real Postgres container (`postgres@sha256:721873c34ceb9f8d8fc265984940dc982404c105f19ad51be9fdc5970a6080ea`, `-e POSTGRES_PASSWORD=test`, free host port, always removed; mark `integration`; skip with an explicit reason if docker is unavailable): collect ~4 s while 3 other connections run `SELECT pg_sleep(2)` and assert a sample shows `wait_event_type='Timeout'`, `wait_event='PgSleep'`, count 3, and that the collector's own connection never appears. Unit tests: interval < 1 raises; unreachable DSN yields stats.errors and no exception; stop() twice is safe; thread is gone after stop().
