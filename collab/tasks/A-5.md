## Scope
Pure driver in `serverlab/analysis/sweep.py` (types and classification already exist in `serverlab/analysis/knee.py`: `StepMeasurement`, `Step`, `KneeResult`, `analyse_sweep`, `classify_all`; do not modify knee.py).

```python
class SweepResult(BaseModel):  # steps: list[Step] (all, sorted by rate), knee: KneeResult,
                               # coarse_order: list[int], bisect_rates: list[int], seed: int
def run_sweep(measure: Callable[[int], StepMeasurement], rate_lo: int, rate_hi: int, seed: int,
              coarse_points: int = 8, max_bisect: int = 6, width_target_pct: float = 5.0) -> SweepResult
```
Algorithm (docs/phases/week3.md s3):
1. Coarse rates: `coarse_points` log-spaced values from rate_lo to rate_hi inclusive, rounded to int (k6 needs integer rates), de-duplicated, ascending. Raise ValueError if rate_lo < 1, rate_hi <= rate_lo or coarse_points < 3.
2. Measure them in a seeded random order (sort by keys from `random.Random(seed).random()`); record that order in `coarse_order`. `measure` is called exactly once per rate.
3. Run `analyse_sweep` on all measurements. If `knee.status != "found"` stop (no bisection): return the result as is.
4. Bisect: while fewer than `max_bisect` extra steps were measured and `knee.width_pct > width_target_pct`: mid = round(sqrt(lo*hi)); if mid <= lo or mid >= hi (integer resolution reached) stop; measure(mid); re-run `analyse_sweep` on ALL measurements so far; update lo/hi from the new knee; if the new knee status is not "found" stop. Record the bisect rates in order.
5. Return everything. Never drop, hide or re-measure a step; invalid steps stay in `steps` with their status.

## Tests (tests/analysis/test_sweep.py), using a fake system with known capacity C
`measure(rate)`: valid, achieved=rate, p99=100 for rate <= C; for rate > C an invalid run with reason "dropped iterations ratio ..." (use the exact marker substrings from knee.py), k6_cpu_pct=20, p99=1000. Cases: bracket contains C and width <= 5% (or max_bisect reached) for C in {50, 100, 200} with rate_lo=10, rate_hi=1000; C above the range -> status above_range and zero bisect steps; C below the lowest rate -> below_range; same seed twice -> identical coarse_order and results; different seeds -> at least two distinct coarse orders over 10 seeds; measure called once per rate (record calls); total measure calls <= coarse_points + max_bisect; invalid argument errors; a step invalid for a non-saturation reason is kept in `steps`, listed in knee.excluded and does not create a knee. Numbers in the fake are test inputs, not measurements; say so in the module docstring.
