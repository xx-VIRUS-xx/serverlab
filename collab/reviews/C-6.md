# Review C-6: API target

Verdict: **APPROVED** (merged, then two lead fixes for flaws in the spec, see below)

Reproduced: build, ruff, mypy, tests clean; integration test against a real Postgres passes and cleans up its own containers. `max_waiting=0` (unbounded queue), min=max=POOL_SIZE, errors -> 503 and counted, no access log, pinned base digest and pinned requirements.
Lead fixes after merge (both were gaps in my spec, not the worker's work):
1. `/healthz` borrowed a pooled connection; the compose healthcheck runs every second, so it stole pool capacity and inflated `requests_num`. Now `/healthz` only reports readiness; the single `SELECT 1` runs once at startup.
2. The real `/metrics` omits counters psycopg_pool has not yet touched (e.g. `requests_queued`, `requests_wait_max` at low load), which would make every collector poll fail. `/metrics` now fills those counters with 0, so the contract is always complete.
